# Motion

Three durations, one easing curve, two animation loops — and a global guard that neutralises all of
them for anyone who asks.

| `--motion-fast` | `0.15s` | Colour and opacity on interaction |

## Easing

`--ease-out` is `cubic-bezier(0.16, 1, 0.3, 1)` — a hard decelerate. It starts fast and settles, which
is what makes a hover lift feel responsive rather than sluggish. Use it for everything that animates
in response to input.

There is deliberately no `--ease-in` or `--ease-in-out`: ease-in on an interaction means the element
lags behind the cursor, and nothing in the app has needed a symmetric curve.

## Loops

`--spin-duration` (`0.7s`) drives `UiSpinner`'s single `@keyframes spin`. `--shimmer-duration`
(`1.4s`) drives `UiSkeleton`'s single `@keyframes shimmer`. Before the design system these keyframes
existed in **four** and **two** copies respectively, drifting; `design-tokens.spec.ts` now enforces
the count with a ratchet that fails both when a copy is added and when one disappears.

## Reduced motion

`base.css` carries one global guard rather than a media query per animation:

```css
@media (prefers-reduced-motion: reduce) {
	*,
	*::before,
	*::after {
		animation-duration: 0.01ms !important;
		animation-iteration-count: 1 !important;
		transition-duration: 0.01ms !important;
		scroll-behavior: auto !important;
	}
}
```

Global because the skeleton shimmer and the spinner loop **indefinitely**, which is precisely the
vestibular-trigger case the media query exists for — and an opt-in-per-animation policy means the
next animation someone adds is unguarded by default.

Durations go to near-zero rather than `none` so `transitionend` / `animationend` still fire; JS
waiting on either doesn't hang.

You get this for free. Don't write your own `prefers-reduced-motion` block in a primitive.
